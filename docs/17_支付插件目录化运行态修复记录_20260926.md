# 2026-09-26 支付插件目录化运行态修复记录

## 本轮目标

继续完善 PHP 支付插件目录化架构。只修改：

```text
C:\Users\Administrator\Desktop\重构PHP
```

不修改原 Go 项目、原文件或其它桌面目录。原 Go 插件目录只作为参考，PHP 运行目录固定为：

```text
本地：plugins/pay/<插件名>/
服务器：/www/wwwroot/xarr-php-ys/plugins/pay/<插件名>/
```

## 发现的问题

1. 插件适配器实例缓存检查早于启停状态检查。一个 PHP-FPM 进程中先解析插件，再停用插件，后续请求可能继续使用旧实例。
2. 后台插件列表同时合并注册表和原始清单，返回逻辑重复，刷新接口返回的也不是最终目录插件注册结果。
3. 插件管理动作没有严格限制动作值，未知动作可能被当成普通状态操作。
4. 清单缺少状态字段时会隐式补默认值，无法区分完整插件清单和不完整插件清单。
5. `.env.example` 的安装锁示例错误指向原 Go 项目路径，容易在本地配置时误用其它运行态。

## 实施内容

### 1. `src/Support/PluginRuntime.php`

- 统一扫描 `XARR_PLUGIN_DIR/pay/*` 下的独立目录。
- 要求 `manifest.json` 中的 `name` 合法，并且必须等于目录名。
- 要求 `type`、`enabled`、`running` 明确存在；状态字段必须是布尔值。
- 支付插件还必须明确配置 `adapter_entry`、`account_entry`、`form_entry`，并且三个文件都必须真实存在于本插件目录。
- 运行态文件 `.runtime.json` 格式错误时直接记录插件自检错误，不补默认状态。
- 新增 `diagnostics()`，返回目录名、有效状态和中文错误列表。
- 启停或删除插件后清理注册器缓存。
- 未知插件动作和越界目录均直接失败。

### 2. `src/Support/PaymentPluginRegistry.php`

- `resolve()` 每次先重新读取清单和启停状态，再使用已加载的适配器实例。
- 插件停用或停止后，不会继续命中旧缓存。
- 目录扫描结果仍是唯一插件来源，不保留核心硬编码插件数组。

### 3. `src/Http/Controllers/AdminController.php`

- `/api/admin/plugins/list` 只返回目录注册表结果。
- `/api/admin/plugins/refresh` 返回最终插件列表和 `diagnostics` 自检结果。
- `start`、`stop`、`enable`、`disable`、`remove` 之外的动作直接返回中文错误。
- 启停、删除异常转换为中文 HTTP JSON 错误。

### 4. 测试

新增：

- `tests/PluginRuntimeTest.php`
  - 目录名与清单名校验。
  - 无效插件目录自检。
  - 停用、停止后的解析拒绝。
  - 重新启用和未知动作拒绝。
- `tests/PluginHttpTest.php`
  - 后台插件列表 HTTP 接口。
  - 刷新接口及诊断结果。
  - 后台停用、启用接口和返回状态。
