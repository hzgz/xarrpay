## 2026-09-25 远端通道账号时间字段修复

### 现象

- 测试站 `https://ys.973700.xyz/user/channel/account` 的收款金额显示正常，但卡片显示：
  - `创建时间: NaN-NaN-NaN NaN:NaN:NaN`
  - `更新时间: NaN-NaN-NaN NaN:NaN:NaN`
- 浏览器控制台和 Network 没有额外业务错误。

### 根因

- 本地前端日期函数 `public/user/static/js/date-c1ca18e2.js` 的输入契约是 Unix 秒时间戳；输入 `0` 时显示 `-`。
- 本地 `database/schema.sqlite.sql` 已定义 `pay_account.created_at` 和 `pay_account.updated_at`。
- 服务器测试库 `/www/wwwroot/xarr-php-ys/var/local.sqlite` 的 `pay_account` 仍是旧表结构，实际没有这两列；接口返回记录时字段缺失，前端收到 `undefined` 后产生 `NaN`。
- 这不是日期格式转换错误，也不通过前端增加兜底分支掩盖。

### 处理

- 新增一次性结构升级文件：`deploy/20260925_pay_account_timestamps.sqlite.sql`。
- 在测试站执行：
  - 先备份 `/www/wwwroot/xarr-php-ys/var/local.sqlite`。
  - 对 `pay_account` 增加 `created_at INTEGER NOT NULL DEFAULT 0`。
  - 对 `pay_account` 增加 `updated_at INTEGER NOT NULL DEFAULT 0`。
- 既有账号历史时间未知，保留数据库真实默认值 `0`；前端按既定契约显示 `-`，不虚构创建时间。
- PHP 接口和前端日期函数不增加兼容分支，仍保持单一字段契约。

### 作用

- 旧测试库结构与当前 PHP 接口、SQLite schema、前端日期函数完全一致。
- 新建账号继续由后端写入当前 Unix 秒时间；编辑账号只刷新 `updated_at`。
- 历史账号显示 `-`，不会再显示 `NaN`。
