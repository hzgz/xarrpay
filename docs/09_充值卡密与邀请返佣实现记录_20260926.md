# 2026-09-26 充值卡密、在线充值与邀请返佣实现记录

## 本轮目标

补齐商户财务中心的真实逻辑：

- 充值卡密核销。
- 卡密余额兑换和套餐兑换。
- 在线充值订单创建、支付回调和充值入账。
- 邀请返佣账本、订单返佣、充值返佣。
- 返佣明细查询和佣金划转。
- 所有资金动作一次性落账，重复请求不重复增加余额。

本轮只修改 `C:\Users\Administrator\Desktop\重构PHP`，没有修改旧 Go 工程、生产目录或服务器文件。

## 修改文件

### `src/Support/OptionStore.php`

新增统一配置读取器：

- 读取 `options` 表的原始值。
- 读取布尔值、整数、逗号分隔支付方式和 JSON 配置。
- 作用是让充值和返佣逻辑读取数据库真实配置，不在控制器内写死线上状态。

### `src/Support/RebateService.php`

新增返佣账本服务：

- 读取推荐人 `user.recommend_uid`。
- 读取 `recommend_enable`、`recommend_fee_*`、`recommend_top_up_*` 配置。
- 支持按比例或固定分值计算返佣。
- 订单返佣来源类型为 `order_fee`。
- 充值返佣来源类型为 `top_up`。
- 佣金划转来源类型为 `transfer`，用负数账本记录扣减。
- 使用 `source_key` 唯一约束防止重复订单、重复充值回调和重复来源重复入账。
- MySQL 使用 `FOR UPDATE`，并通过 `UPDATE ... rebate_balance >= :amount` 防止并发超额划转。

### `src/Support/RechargeCardService.php`

新增充值卡密核销服务：

- 卡密不能为空。
- 锁定卡密和当前商户。
- 校验卡密存在、卡密启用、分组启用、卡密未使用。
- 校验分组总次数、单商户时间间隔和每日次数限制。
- `value_type=1` 增加余额，单位为分。
- `value_type=2` 校验启用套餐，并写入当前商户 `settings.meal` 的套餐和到期时间。
- 原子更新 `use_uid/use_time`。
- 写入 `recharge` 和 `balance_log`。
- 卡密兑换余额后按充值返佣规则产生返佣。
- 失败时事务回滚，不产生半笔入账。

### `src/Support/RechargeService.php`

新增在线充值服务：

- 校验余额充值开关和最低充值金额。
- 校验充值支付方式必须在 `pay_recharge_pay_type` 中。
- `pay_recharge_type=epay` 时要求 host、pid、key 全部存在，生成带签名的易支付地址。
- `pay_recharge_type=default` 时要求 `pay_default_uid` 对应启用商户，并且该商户有启用的支付账号和收款码。
- 默认模式创建一条官方收款订单，订单参数绑定目标充值订单和目标商户。
- 易支付回调校验 pid、签名、交易状态和金额。
- 充值结算只处理一次，重复回调只返回 `already_paid=true`。

### `src/Support/OrderSettlementService.php`

修改订单首次成功结算：

- 普通订单继续给订单所属商户增加余额。
- 普通订单首次成功后调用订单返佣。
- 充值支付订单识别 `device=recharge` 和 `param.recharge_order_id/target_uid`，转由 `RechargeService` 给目标商户入账。
- 重复回调不会重复更新订单余额、充值余额或返佣。

## 数据库语义

- 当前 PHP 卡密状态约定：`status=1` 为启用，`status=0` 为停用；是否已使用由 `use_uid > 0` 和 `use_time` 判断。
- 旧 Go 的 `cards/card_groups` 数字状态没有直接覆盖 PHP 当前后台契约。
- 金额统一使用整数分。
- 返佣账本 `balance > 0` 表示增加，`balance < 0` 表示佣金划转扣减。
- `source_key` 是返佣业务来源幂等键，唯一约束拒绝重复来源。

## 配置要求

返佣必须同时满足：

- `recommend_enable=1`
- 对应场景开关为 `1`
- 对应返佣金额或比例大于 `0`

充值必须满足：

- `pay_recharge_enable=1`
- `pay_recharge_type=epay`：`pay_recharge_epay_host`、`pay_recharge_epay_pid`、`pay_recharge_epay_key` 全部配置。
- `pay_recharge_type=default`：`pay_default_uid` 对应启用商户，且该商户有启用支付账号和收款码。
- `pay_recharge_pay_type` 包含前端提交的支付方式。

配置缺失时返回中文错误并且不创建假充值订单。
