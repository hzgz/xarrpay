# 商户添加通道支付方式与插件通道修复记录

日期：2026-09-27

## 1. 问题现象

商户中心添加收款账号时，支付方式和通道下拉为空或互相过滤后没有可选项。选择通道后，前端请求 `/api/channel/gateway` 出现 HTTP 422，并伴随 `Uncaught (in promise)`。后台控制台还会显示 Vue Router 的 `Navigation cancelled`。

## 2. 根因

1. `/api/pay/conf` 只返回系统配置，没有返回前端 `confStore` 需要的 `pay_type` 和 `channels`。
2. `pay_channel.type` 的字段语义是支付方式值，必须是 `alipay`、`wechat` 等支付方式值；本地 `demo` 误写成了 `static`。
3. 插件清单没有声明支持的支付方式，系统无法判断一个插件通道是否能服务当前支付方式。
4. 商户表单和网关接口只校验通道代码，没有同时校验支付方式、通道类型、插件状态和插件支持范围。
5. 网关请求失败没有在前端统一处理，导致 Promise 未捕获；商户前端错误处理脚本也没有过滤导航取消状态。

## 3. 本次修改

### 插件契约

以下支付插件清单新增 `pay_types`：

- `plugins/pay/static_code/manifest.json`：`alipay`、`wechat`
- `plugins/pay/jk_wechat_app/manifest.json`：`wechat`
- `plugins/pay/yun_qnm_lz/manifest.json`：`wechat`
- `plugins/pay/yun_wechat_gj_xd/manifest.json`：`wechat`
- `plugins/pay/yun_wechat_yyb_xd/manifest.json`：`wechat`

`src/Support/PluginRuntime.php` 现在要求支付插件必须配置非空的 `pay_types` 字符串数组。清单缺失时进入无效插件诊断，不生成假通道。

`src/Support/PaymentPluginRegistry.php` 新增：

- `supportsPayType()`：判断插件清单是否声明支持指定支付方式。
- `usableForPayType()`：同时要求支付方式支持、插件已启用、插件正在运行、支付适配器和账号适配器均可解析。

`src/Support/PaymentPluginCatalog.php` 返回插件真实的 `pay_types`。

### 后端接口

`src/Http/Controllers/PayController.php`

- `/api/pay/conf` 保留系统配置。
- 新增真实启用的 `pay_type`。
- 新增真实启用、支付方式匹配、插件启用并运行的 `channels`。
- 停用支付方式、停用通道、无效插件或插件不支持当前支付方式的记录不会返回。

`src/Http/Controllers/MerchantController.php`

- 商户通道列表只返回可用的支付方式/通道/插件组合。
- `/api/channel/form-items` 要求 `pay_type` 和通道代码同时存在，并校验二者匹配。
- `/api/channel/gateway` 要求支付方式和通道匹配后才读取真实网关。
- 创建或编辑收款账号时严格校验：
  - 支付方式存在且启用；
  - 通道存在且启用；
  - `pay_channel.type === pay_type`；
  - 插件存在、启用、运行；
  - 插件声明支持该支付方式。

`src/Http/Controllers/AdminController.php`

- 后台创建/编辑通道必须选择已启用支付方式。
- 插件必须存在、启用、运行，并声明支持该支付方式。
- 后台通道列表补充插件支持范围和真实通道元信息。

### 前端错误处理

`public/user/static/js/unimplemented-feature-notice.js`

- 过滤 Vue Router 的 `Navigation cancelled from ...` 正常取消导航。
- 对真实 HTTP 4xx/5xx 显示后端中文错误。
- 拦截表单字段和网关请求失败时的未捕获 Promise及控制台重复错误。

`public/admin/static/js/unimplemented-feature-notice.js`

- 增加同样的导航取消过滤。

`public/router.php`

- 给前后台错误处理脚本增加 `20260927-pay-channel` 版本参数，避免浏览器继续使用旧缓存。
