# 24_商户ID免密密钥通道插件修复记录_20260927

## 背景

本次处理用户实测反馈：

- 商户默认 ID 不是从 10000 开始。
- 后台创建商户后提示找不到 ID。
- 后台免密登录不生效。
- 后台创建商户触发二次认证。
- 商户密钥带 `-`，不是固定 32 位。
- 商户创建通道/账号时通道弹窗无法选择或后续不可用。
- 后台插件没有正确启用，批量启用/停止报错。

处理范围只在 `C:\Users\Administrator\Desktop\重构PHP`。

## 改动清单

### 1. 商户 ID 真实从 10000 起步

新增文件：

- `src/Support/MerchantIdentity.php`

实现：

- `MerchantIdentity::FIRST_ID = 10000`
- `MerchantIdentity::nextId(PDO $db)` 读取 `user` 表最大 ID，返回 `max(10000, max_id + 1)`。

修改文件：

- `src/Http/Controllers/AdminController.php`
- `src/Http/Controllers/MerchantFeatureController.php`

改法：

- 后台创建商户和前台注册都显式写入 `id`。
- 空库首个商户写入真实数据库 ID `10000`，不是前端显示伪造。
- MySQL schema 增加 `ALTER TABLE user AUTO_INCREMENT = 10000;`。
- SQLite 通过显式插入 `10000`，后续 AUTOINCREMENT 自动递增。

作用：

- 和旧 Go 项目保持一致，商户号从 `10000` 开始。
- 避免创建返回 ID 与数据库真实 ID 不一致导致“找不到 ID”。

### 2. 商户密钥统一 32 位无连接符

新增统一生成：

- `MerchantIdentity::appSecret()` 返回 `bin2hex(random_bytes(16))`。

修改位置：

- 后台创建商户：`AdminController::createUser()`
- 前台注册：`MerchantFeatureController::register()`
- 商户重置密钥：`MerchantController::resetSecret()`

改法：

- 删除 `local-` 前缀。
- 删除 48 位密钥生成。
- 后台手动传入密钥时校验 `/^[a-f0-9]{32}$/i`。

作用：

- 新建、注册、重置全部生成固定 32 位十六进制密钥。
- 不再出现 `local-xxxx` 或带 `-` 的密钥。

### 3. 后台创建商户不再触发二次认证

修改文件：

- `src/Http/Controllers/AdminController.php`
- `tests/AdminSecurityTest.php`

改法：

- `createUser()` 删除 `user.create` 的 step-up 消费。
- 保留编辑商户、删除商户、余额调整、返佣余额调整等高风险操作的二次认证。

作用：

- 后台创建商户按旧版体验直接创建。
- 敏感修改仍需要二次确认。

### 4. 免密登录票据过期与兑换修复

修改文件：

- `src/Http/Controllers/MerchantFeatureController.php`

改法：

- `/api/tickets/data` 对 `app_login_ticket.status IN (1,2)` 的过期票据统一标记为 `5`。
- 返回数据增加 `kind` 字段，便于前端区分票据类型。
- 修复过期 `admin_login` 票据仍可被消费的漏洞。

现有前端入口：

- `public/user/static/js/ticket-login-fix.js`
- `public/user/index.html` 已在主 bundle 前加载该脚本。

作用：

- 后台生成 `/login?ticket=...` 后，前端先调用 `/api/tickets/data` 兑换真实 token，再进入 `/user`。
- 票据一次性消费，过期不可用。

### 5. 通道/收款账号插件状态校验

修改文件：

- `src/Http/Controllers/AdminController.php`
- `src/Http/Controllers/MerchantController.php`
- `src/Support/PaymentPluginCatalog.php`

改法：

- 创建/编辑支付通道时强制校验插件已安装、已启用、正在运行，并且 adapter/account/form 入口可用。
- 商户创建收款账号时同样校验插件运行态。
- 表单项读取 `PaymentPluginCatalog::formItems()` 也校验插件启用和运行，避免弹窗展示后保存失败。

作用：

- 后台创建通道必须选可用插件。
- 商户弹窗不会选择到停用或不可运行通道。

### 6. 插件启用/停止/批量操作修复

修改文件：

- `src/Http/Controllers/AdminFeatureController.php`

改法：

- `appItemsAction()` 不再把传入 `uuid` 直接当插件目录名。
- 新增 `findAppItem()`，按 `uuid/plugin_name/name` 查应用，再取真实 `plugin_name` 操作。
- 批量启用/停止/卸载同样走应用映射。
- 仅允许类型 `1/4/6` 执行启用、停止、重载。
- 应用列表增加：
  - `plugin_name`
  - `can_enable`
  - `can_disable`
  - `can_reload`
  - `can_uninstall`
  - `status`
  - `running`

作用：

- 后台插件列表可正确显示启用/禁用/重载按钮。
- 批量启用、批量停止不会因为 UUID/目录名混用报“插件不存在”。
- 后续接 Go 的 `app_items.uuid` 时仍能区分 UUID 和插件目录名。

### 7. 测试夹具同步

修改文件：

- `scripts/init-local-fixtures.php`

改法：

- 测试商户从 `id=1` 改为 `id=10000`。
- 测试商户密钥改为 `0123456789abcdef0123456789abcdef`。
- 关联账号、支付码、订单 UID 同步改为 `10000`。

作用：

- 本地夹具与线上安装逻辑一致，避免测试仍验证旧错误行为。

## 下次更新核对点

- 新建空库后第一个商户 ID 必须为 `10000`。
- 后台创建商户不应弹二次认证。
- 新建/注册/重置商户密钥必须匹配 `^[a-f0-9]{32}$`。
- `/login?ticket=...` 必须兑换真实 token，不能把 ticket 直接当 token。
- 通道必须绑定已启用、运行中的支付插件。
- 插件后台列表必须显示启用/禁用/重载/卸载。
- 批量启用/停止必须按 `uuid -> plugin_name` 映射操作。
