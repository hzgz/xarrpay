# 2026-09-27 后台管理员二次认证与创建商户修复记录

## 1. 本轮目标

修复后台创建商户报错、免密跳转前置认证链路不完整，以及后台敏感写操作没有真正消费二次认证票据的问题。

本轮只修改 `C:\Users\Administrator\Desktop\重构PHP`，没有修改 Go 原项目，也没有修改其它目录。

## 2. 根因

后台商户新增、编辑、删除、余额和佣金操作已经由前端调用：

1. `security.beginStepUp()`
2. `security.finishStepUp()`
3. 在实际写请求中发送 `X-Step-Up-Ticket`

但是后端共享路由原来始终调用 `MerchantFeatureController`：

```text
/api/security/step-up/begin
/api/security/step-up/finish
/api/security/step-up/send-code
```

商户控制器只识别 `user.token`。后台请求携带的是 `staff.token`，因此后台 token 会被当成商户 token，返回“登录已失效”。

同时，`AdminController` 的商户写接口只校验管理员登录，没有消费 `X-Step-Up-Ticket`，导致前端即使完成二次认证，票据也没有形成服务端安全边界。

本地浏览器首次真实点击还发现运行态 `var/local.sqlite` 是旧库，缺少源码 schema 已定义的 `security_ticket` 表，因此发起管理员二次认证时出现 HTTP 500。该问题属于运行库未执行迁移，不是 PHP 业务代码语法错误。

## 3. 修改文件

### `src/Http/Controllers/AdminController.php`

新增：

- `stepUpBegin()`：识别当前管理员，创建 `security_ticket`，票据 `uid` 绑定 staff ID。
- `stepUpFinish()`：支持管理员当前密码或 TOTP 动态口令验证，成功后将票据标记为 `verified`。
- `stepUpSendCode()`：未配置邮件/短信服务时返回明确中文 501。
- `isStaffToken()`：供共享路由判断当前 Authorization 是否属于有效 staff。
- `consumeStepUpTicket()`：严格校验票据归属、用途、有效期、状态，并使用条件更新原子消费。

接入管理员二次认证的操作：

| 操作名 | 接口 |
| --- | --- |
| `user.create` | 创建商户 |
| `user.edit` | 编辑商户 |
| `user.remove` | 删除商户 |
| `user.balance.set` | 设置商户余额 |
| `user.rebate_balance.set` | 设置商户返佣余额 |

缺少票据、票据归属错误、用途不匹配、已过期、已消费和重放都会返回中文错误，不能继续写入。

### `src/Application.php`

共享路由现在根据 Authorization token 明确分流：

- staff token：进入 `AdminController` 管理员二次认证。
- merchant token：继续进入 `MerchantFeatureController` 商户二次认证。

同时补充后台前端实际使用的路径：

```text
/api/admin/security/step-up/begin
/api/admin/security/step-up/finish
/api/admin/security/step-up/send-code
```

商户原有路径保持：

```text
/api/security/step-up/begin
/api/security/step-up/finish
/api/security/step-up/send-code
```

### `tests/AdminSecurityTest.php`

新增管理员安全回归测试，覆盖：

- 管理员专用二次认证路由。
- 共享路由对管理员和商户的正确分流。
- 管理员密码验证。
- 创建商户带票据成功。
- 创建商户缺票据失败。
- 票据重放失败。
- 编辑商户、设置余额、设置返佣余额、删除商户均要求对应用途票据。

### `scripts/browser-admin-test.py`

将后台 token 注入方式改为：

1. 先加载后台登录页面。
2. 页面进入同源后直接执行 `localStorage.setItem("token-admin", token)`。
3. 再导航到 `/admin`。

避免 `Page.addScriptToEvaluateOnNewDocument` 注入时序不稳定导致测试脚本误判登录失败。

### `scripts/browser-admin-menu-test.py`

同步采用页面加载后直接设置 `token-admin` 的方式，保持菜单巡检和后台主页面巡检一致。
