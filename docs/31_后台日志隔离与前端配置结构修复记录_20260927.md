## 2. 本轮确认的问题

### 2.1 商户端支付配置未加载时直接调用 filter

浏览器报错：

```text
Cannot read properties of undefined (reading 'filter')
```

根因是支付配置接口返回前，前端状态中的 `payConf.channels` 尚未形成数组，但 `getPayChennelList()` 直接执行了 `.filter()`。

### 2.2 商户通道详情字段结构不完整

浏览器报错：

```text
Cannot read properties of undefined (reading 'day_order_amount')
```

根因是后端只返回了数据库中的扁平 `day_amount_limit`，前端按旧版契约读取嵌套字段 `limit_rule.day_order_amount`。

### 2.3 后台日志扫描串站

旧逻辑扫描了旧 Go 项目、服务器公共日志、PHP-FPM、Nginx 和配置目录，导致后台日志列表可能展示其它站点日志。

本轮后端日志范围固定为当前 PHP 项目目录内：

```text
var/*.log
runtime/logs/*.log
```

不再读取、展示、下载或删除其它站点日志。

## 3. 实际修改

### 3.1 `src/Http/Controllers/AdminFeatureController.php`

修改 `logRoots()`：

- 删除旧 Go 项目日志目录；
- 删除 `/www/wwwlogs`；
- 删除 PHP-FPM、Nginx 和配置目录；
- 只保留当前项目 `var` 和 `runtime/logs` 的日志文件；
- 继续使用项目内相对路径返回，禁止暴露服务器绝对路径。

作用：后台日志功能只能访问本 PHP 项目的运行日志，解决日志串站问题。

### 3.2 `src/Http/Controllers/MerchantController.php`

修改通道详情接口：

- 解析 `options` JSON；
- 解析 `bind_pay_type` JSON；
- 返回完整 `limit_rule` 对象；
- 将数据库真实字段 `day_amount_limit` 映射到 `limit_rule.day_order_amount`。

修改商户通道保存参数读取：

- 支持从请求的 `limit_rule.day_order_amount` 读取每日限额；
- 不创建假数据，不在接口层返回空成功。

作用：商户通道详情与旧版前端契约一致，编辑后保存的限制字段仍写入真实数据库字段。

### 3.3 前端 modern/legacy bundle

同步修改以下三个实际加载文件：

```text
public/user/static/js/conf-30b666d8.js
public/admin/static/js/background-5abb4136.js
public/admin/static/js/background-legacy-b150e436.js
```

修改内容：

- `getPayChennelList()` 只有在 `channels` 是真实数组时才过滤；
- 支付配置刷新只接受真实对象响应，不把数组或其它类型写入配置状态；
- modern 和 legacy 两套 bundle 同步修改。

作用：接口配置加载期间不会再触发未定义 `.filter()`；不会因错误响应结构污染全局支付配置状态。

### 3.4 回归测试


新增断言：

- 日志列表不得出现 `legacy/`、`wwwlogs/`、`php-fpm/`、`nginx/`；
- 商户通道详情必须返回 `limit_rule.day_order_amount`；
- `options` 和 `bind_pay_type` 必须按真实 JSON 结构解析。
