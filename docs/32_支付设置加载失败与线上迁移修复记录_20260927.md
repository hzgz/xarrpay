## 2. 用户现象

商户中心点击“支付设置”后提示：

```text
加载支付设置失败
```

## 3. 根因确认

### 3.1 线上代码不是当前版本

线上 `MerchantFeatureController::paySettings()` 仍返回旧版字段：

```text
balance_notice
pay_wait_time
notify_method
epay_notify_method
remove_subject
random_amount_min
random_amount_max
pay_template
```

当前前端实际执行：

```text
o.data.user_pay_types.split(",")
```

旧接口没有 `user_pay_types`，因此页面会进入统一错误提示。

### 3.2 线上数据库未执行本轮迁移

线上 `user` 表原本没有：

```text
last_login_ip
last_login_time
```

但线上当前 PHP 登录代码已经执行：

```sql
UPDATE user
SET token=:token,
    last_login_ip=:last_login_ip,
    last_login_time=:last_login_time
WHERE id=:id
```

结果是登录请求可能在写入登录信息时失败，页面随后没有有效商户 token，支付设置接口只能返回“未登录”。

## 4. 实际修改

### 4.1 `src/Http/Controllers/MerchantFeatureController.php`

同步当前支付设置接口字段，GET 返回完整结构：

```text

```

作用：与当前商户中心支付设置前端契约一致，支付配置加载和保存使用同一组真实字段。

### 4.2 `src/Http/Controllers/MerchantController.php`

同步当前登录审计逻辑：

- 登录成功时写入真实 IP；
- 登录成功时写入真实时间；
- 登录日志区分 `login_type`；
- MFA 待验证阶段不提前记为成功登录。

作用：登录后商户资料、最近登录和登录日志读取同一份真实数据。

### 4.3 数据库结构文件

同步：


迁移新增：

```text

```

已有成功登录日志用于回填商户最近登录 IP 和时间，没有生成假记录。

## 7. 下次更新核对项

更新线上 PHP 代码时，不能只覆盖 `src/` 和 `public/`，必须同时核对：

1. 当前版本是否包含最新 `MerchantFeatureController::paySettings()` 字段；
2. 线上 SQLite 是否已执行对应 `deploy/*.sqlite.sql` 迁移；
3. 登录代码使用的字段是否已存在于线上数据库；
4. 替换代码后是否重载 PHP-FPM；
5. 使用真实商户 token 验证 `/api/setting/pay`，再做浏览器点击验收。
