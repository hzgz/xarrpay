# 2026-09-26 后台存储孤立文件实现记录

## 本轮目标

把后台存储管理中的孤立文件扫描和清理从固定空结果改为真实逻辑：

- `GET /api/admin/storage/file/orphan/scan`
- `POST /api/admin/storage/file/orphan-delete`

本轮只修改 `C:\Users\Administrator\Desktop\重构PHP`，不修改旧 Go 工程、服务器原 Go 目录、生产数据库或其他目录。

## 原问题

原实现对孤立文件操作只返回固定成功结果：

- 扫描固定返回“未发现孤立文件”。
- 清理固定返回 `removed=0`。
- 未读取 `public/uploads` 的真实文件。
- 未对 `upload_file` 数据库登记关系进行判断。
- 未阻止站外路径删除。

这会让后台看起来操作成功，但实际没有完成任何文件管理工作，属于未上线能力伪造成功。

## 修改文件

### `src/Http/Controllers/AdminFeatureController.php`

#### `storageOrphanScan()`

实现步骤：

1. 校验管理员登录态。
2. 将 `public/uploads` 作为唯一扫描根目录。
3. 查询 `upload_file.path`，将已登记且位于上传目录内的真实路径加入保护集合。
4. 递归遍历上传目录中的真实文件。
5. 已登记文件跳过，未登记文件作为孤立文件返回。
6. 返回前端需要的路径、URL、名称、大小、MIME、修改时间、数量和总数。
7. 没有孤立文件时只返回真实的“未发现孤立文件”，不伪造文件列表。

#### `storageOrphanDelete()`

实现步骤：

1. 校验管理员登录态。
2. 接收 `orphans[]` 或 `files[]`。
3. 将 URL 路径或文件路径解析到 `public/uploads` 下。
4. 拒绝目录外路径、路径穿越、目录本身、非文件和不存在的文件。
5. 删除前再次查询 `upload_file.path`，已登记文件一律跳过。
6. 返回实际删除数量、删除字节数和跳过列表。
7. 未选择文件时返回中文 422，不写假成功。

#### 新增私有方法

- `uploadRoot()`：统一计算上传根目录。
- `resolveUploadPath()`：统一做路径解析和目录边界校验。
- `uploadFileDescriptor()`：统一生成前端文件列表字段。

作用：扫描和删除共享同一套路径边界规则，避免扫描结果与删除目标不一致，也避免误删已登记文件或站外文件。

### `src/Application.php`

修正并注册实际前端契约路径：

- `GET /api/admin/storage/file/orphan/scan`
- `POST /api/admin/storage/file/orphan-delete`

此前只注册了 `/orphan-scan` 形式，测试调用真实契约路径时会收到 404。此次改为实际路径，不增加假成功兼容分支。

### `tests/StorageOrphanTest.php`

新增隔离 HTTP 回归测试：

- 创建临时 SQLite 数据库。
- 创建一个已登记文件和一个未登记文件。
- 验证扫描只返回未登记文件。
- 验证清理后孤立文件真实消失。
- 验证已登记文件仍然存在。
- 验证站外路径不能被删除。
- 测试结束清理临时数据库、文件和 PHP 服务。

### `tests/MfaHttpTest.php`、`tests/MfaSecurityFlowTest.php`

修复 HTTP 回归测试的运行态清理和 session 目录：

- Windows 下按测试服务 PID 树回收 PHP 内置服务，避免 `proc_close()` 挂起。
- 测试服务显式使用项目 `var/.mfa-*-session-*` 临时目录保存 session。
- 测试服务启动前自动选择可用验证码字体：已有 `XARR_CAPTCHA_FONT` 时保留，否则使用 Windows Arial 或 Linux DejaVu。
- 测试结束删除临时 session 文件和目录。

作用：本地 Windows 和服务器 Linux CLI 都不再依赖默认 `session.save_path` 或 PHP-FPM 独有环境变量；不改变 MFA 业务接口和断言。

## 数据和安全规则

- 只扫描 `public/uploads`。
- `upload_file` 中已登记的文件不属于孤立文件。
- 删除前重新查库，避免扫描后文件被登记仍遭删除。
- 所有路径必须解析到上传根目录的子文件。
- 绝对路径、URL 路径和相对路径都经过同一套边界校验。
- 不删除数据库登记关系，不改变业务文件记录。
