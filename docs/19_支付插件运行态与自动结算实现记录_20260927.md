## 2. 从零盘点结论

### 2.1 已发现的明确 bug

文件：

```text
src/Support/PluginAccountService.php
```

二维码登录检查成功分支直接使用未初始化的 `$options`：

```php
$options = array_replace($options, self::decodeArray($result['account_options'] ?? []));
```

这会在二维码登录成功回写账号配置时触发运行时错误，导致登录态不能保存。

### 2.2 原有运行态缺口

- `PaymentPlugin` 只有创建和主动查询，没有统一的心跳、定时任务和流水解析契约。
- `AccountPlugin` 只有账号动作和二维码登录。
- `notify-worker.php` 只处理商户异步通知队列，不能替代支付插件流水 worker。
- `third_order_log` 是后台通用日志，不包含插件、账号、商户、金额、流水时间、唯一流水号和匹配订单字段。
- `pay_account_ext` 只有简单的 `last_seen_at`、`last_error`，没有任务状态和任务历史。

## 3. 文件级修改记录

### 3.1 `src/Payment/RuntimePlugin.php`

新增独立运行态接口：

- `heartbeat(PDO $db, array $account, int $now)`
- `cron(PDO $db, array $account, int $now)`
- `parseMessage(array $message, array $account)`

作用：把运行态能力从支付创建契约中分离，插件必须显式实现，不能由服务层猜测或兜底。

### 3.2 `src/Support/PluginAccountService.php`

修改：

- 二维码登录检查成功后先执行 `$options = self::options($account)`。
- 新增全能码账本请求方法 `qnmBillAdapter()`。
- 新增统一金额转换 `amountInCents()`。
- 新增 Unix 秒、毫秒和日期字符串转换 `timestamp()`。

作用：

- 修复二维码登录成功回写 bug。
- 账本插件只调用明确的真实接口，不在没有响应时返回假流水。
- 插件返回的元、分、毫秒和日期时间先标准化，再进入流水表。

### 3.3 `src/Payment/JkWechatAppPlugin.php`

新增 `RuntimePlugin` 实现：

- 心跳开关关闭时明确返回“插件未开启客户端心跳”。
- 从 `pay_account_ext.last_seen_at` 判断客户端是否在心跳超时窗口内。
- 服务端 cron 明确拒绝，要求客户端消息上报。
- 解析微信通知标题/内容中的收款金额、流水号、交易时间、备注和买家。
- 没有金额、流水号或收款通知特征时直接抛出中文错误。

作用：支持 APP 监控插件的运行态判断和消息标准化；不在服务端伪造客户端消息。

### 3.4 `src/Payment/YunQnmLzPlugin.php`

新增 `RuntimePlugin` 实现：

- 使用已保存的 `custom_session_key`、`tally_openid` 调用账本接口。
- 递归识别账本返回的流水项。
- 只接受收入类型，排除退款、红包、转账、消费、充值。
- 使用 `poll_window_seconds` 做时间窗口过滤，最小 60 秒。
- 输出第三方流水号、分金额、交易时间、备注、买家和原始数据。
- 没有登录态时明确返回中文失败。

作用：全能码账号可以被 worker 周期性拉取真实账本流水。

### 3.5 `src/Payment/WechatCloudXdPlugin.php`

新增 `RuntimePlugin` 实现：

- 账号没有 SID 时明确返回未登录。
- 要求后台在账号选项中填写真实 `flow_endpoint`。
- 支持明确的 GET 或 POST 请求方法。
- 请求参数包含 SID、账号 ID、账号类型、店铺 ID、查询数量和时间范围。
- 过滤非收入流水和退款、红包、转账、消费、充值。
- 统一标准化流水字段。
- 未配置真实接口时明确失败，不返回空成功。

对应表单新增文件：

```text
plugins/pay/yun_wechat_gj_xd/form.php
plugins/pay/yun_wechat_yyb_xd/form.php
```

新增字段：

- `flow_endpoint`
- `flow_http_method`

### 3.6 `src/Support/PluginRuntimeService.php`

新增运行态编排服务：

1. 查询启用的收款账号和启用通道。
2. 根据通道绑定的插件清单读取能力。
3. 清单声明 `heartbeat` 或 `cron`，但 PHP 适配器没有 `RuntimePlugin` 时直接失败。
4. 执行心跳并写入 `plugin_runtime_state`。
5. 执行 cron，标准化并写入 `third_order`。
6. 通过插件、账号、第三方流水号唯一键去重。
7. 按收款账号、通道插件、商户归属、金额、创建时间、过期时间匹配待支付订单。
8. 匹配成功后调用 `OrderSettlementService`。
9. 写入流水状态：
   - `0`：待处理
   - `1`：等待匹配
   - `2`：已结算
   - `3`：超时拒绝
   - `4`：处理失败
10. 记录 `plugin_runtime_log`，保留 worker、开始时间、结束时间、流水数量和中文错误。

严格行为：

- 重复流水不会重复入库。
- 金额不一致不会结算。
- 账号归属不一致不会跨商户结算。
- 超出时间窗口不会结算。
- 运行异常不会转成支付成功。
