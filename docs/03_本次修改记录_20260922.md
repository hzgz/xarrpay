## 本次新增和修改

### 0. 接续修改原则

- 参考旧版已确认的请求流程和现有静态 UI 的真实 API 契约。
- 没有把旧模板目录当作 PHP 模板使用；支付页面资源改为本地 `public/pay/assets` 的明确路径。
- 本地和生产分别使用明确数据库配置：本地 SQLite，生产环境变量 MySQL；不做双路径兜底。

### 1. 新增支付页和收银台控制器

新增 `src/Http/Controllers/PayController.php`，实现订单详情、状态轮询、支付方式选择、支付方式列表、二维码/文本收款信息、收银台密钥解析和收银台订单创建。数据全部读取当前数据库，不写生产插件正文。

作用：让支付页静态 JS 的真实调用链可以落到 PHP API，不再停留在接口骨架。

### 2. 新增本地 SQLite schema 和初始化脚本

新增 `database/schema.sqlite.sql`、`scripts/init-local.php`、`var/`，提供 staff、user、order、pay_type、pay_channel、pay_account、options 表和明确的本地演示数据。

作用：不依赖生产数据库即可从 0 启动和验收；初始化脚本可重复执行，不复制真实密钥。

### 3. 修复 SQLite 查询路径

统计接口改为 Unix 时间范围比较，避免执行 MySQL 专用的 `UNIX_TIMESTAMP`、`FROM_UNIXTIME`、`INTERVAL`。

### 4. 修复支付页面模板占位符

`public/pay/index.html`、`separate.html`、`status.html` 改为 `/pay/assets/...` 明确资源路径和静态标题，移除 `${.templateAssets}`、`${... | get_option}` 等未渲染占位符。

### 5. 新增部署和接口文档

新增 `docs/部署教程.md`、`docs/04_接口完成清单.md`，所有说明继续集中在 `docs` 目录。

### 1. 新增 `src/Support/Captcha.php`

- 使用 PHP session 保存验证码 ID、验证码文本和过期时间。
- 使用 GD 生成 PNG 图片并返回 `data:image/png;base64,...`。

- 作用：兼容后台登录页要求的 `captcha_type`、`captcha_id`、`captcha_base64`，不使用固定验证码。

### 2. 新增 `src/Http/Controllers/AdminController.php`

- `/api/plugins/list`：只读取服务器挂载目录中的插件 manifest，不复制插件正文到本地。
