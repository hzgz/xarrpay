# 2026-09-26 支付插件目录化重构记录

## 变更原因

上一版 PHP 支付插件虽然能调用适配器，但插件名称、显示信息和表单字段主要写在核心 `src/` 中。这与原 Go 项目的固定插件根目录和独立插件目录不一致，也导致插件目录为空时核心仍可能显示内置插件。

本轮改为目录驱动：

```text
plugins/
└── pay/
    ├── static_code/
    │   ├── manifest.json
    │   ├── adapter.php
    │   └── form.php
    ├── jk_wechat_app/
    ├── yun_qnm_lz/
    ├── yun_wechat_gj_xd/
    └── yun_wechat_yyb_xd/
```

固定插件根目录由 `XARR_PLUGIN_DIR` 指定，支付插件固定扫描 `XARR_PLUGIN_DIR/pay/*/manifest.json`。

## 修改内容

### `src/Support/PluginRuntime.php`

- 默认插件目录改为当前工程的 `plugins`，生产环境继续使用 `XARR_PLUGIN_DIR`。
- 增加 `paymentDirectory()`，统一返回支付插件根目录。
- `manifests()` 只扫描每个插件独立目录下的 `manifest.json`。
- 清单必须有合法 `name`，且清单名称必须与插件目录名一致。
- `enabled`、`running` 必须在清单中明确写成布尔值，不再根据缺失字段自动补状态。
- 读取每个插件目录的 `.runtime.json` 运行状态；运行态格式错误直接使该插件自检失败。
- 增加 `manifest()`，按插件名获取单个清单。
- 增加 `entryPath()`，限制入口文件只能位于当前插件目录内，禁止绝对路径、目录穿越和目录外文件。
- 增加 `diagnostics()`，返回每个插件目录的有效性和中文错误原因，供后台刷新和排查使用。
- 启停、删除动作完成后清理适配器缓存，避免当前 PHP 进程继续使用已停用或已删除的插件。

### `src/Support/PaymentPluginRegistry.php`

- 删除原先写死的插件名称和核心内置实例数组。
- `catalog()` 改为完全读取 `PluginRuntime::manifests()`。
- `resolve()` 只允许加载存在于 `plugins/pay/<name>/manifest.json` 的插件，并检查启用、运行状态、入口文件、入口返回类型和名称一致性。
- 每次解析先重新读取清单状态，再使用适配器缓存；插件停用或停止后不会继续命中旧实例。
- 保留 `available()` 作为公开能力查询，但它现在只检查目录插件是否可以实际加载，不是硬编码白名单。

### `src/Support/PaymentPluginCatalog.php`

- 删除按插件名写死的核心表单定义。
- 改为从插件清单读取 `form_entry`，加载当前插件目录下的 `form.php`。
- 清单不存在、适配器不可用、表单入口不存在、入口返回类型错误和表单项缺少名称时直接报错。
- `channelMeta()` 改为读取清单中的 `plugin_options` 和 `actions`。

### `plugins/pay/*`

新增 5 个独立支付插件目录：

- `static_code`
- `jk_wechat_app`
- `yun_qnm_lz`
- `yun_wechat_gj_xd`
- `yun_wechat_yyb_xd`

每个目录包含 `manifest.json`、`adapter.php`、`account.php`、`form.php`。适配器业务实现仍在 `src/Payment`，由插件目录入口装配；新增插件时不需要修改核心注册器。

## 明确失败条件

- `plugins/pay` 不存在或没有清单：插件列表为空，绑定通道时提示插件未安装。
- `enabled=false` 或 `running=false`：不能解析支付插件。
- 清单缺少 `adapter_entry`、`account_entry` 或 `form_entry`：对应能力不可用，不自动补默认入口。
- 入口文件不存在、越界或返回类型错误：插件不可用。
- 适配器名称与清单名称不一致：拒绝加载。
- 真实收款账号、SID、云端网关或上游请求缺失：适配器明确失败，不生成模拟支付成功。
