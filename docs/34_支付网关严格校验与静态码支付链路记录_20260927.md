# 支付网关严格校验与静态码支付链路记录

日期：2026-09-27

## 1. 本轮目标

在支付方式和插件通道修复完成后，继续把后台支付网关配置和本地静态码支付链路跑通，避免后台能够保存实际不可用的网关记录。

## 2. 发现的问题

`/api/admin/channel/gateway/create`、编辑和批量导入原来只检查名称和地址是否为空，存在以下问题：

- 可以保存空支付方式或空通道；
- 可以保存支付方式与通道类型不匹配的记录；
- 可以保存停用通道；
- 可以保存插件未启用、未运行或不支持当前支付方式的记录；
- 地址不是完整 HTTP/HTTPS 地址时也能写入；
- `options` 传入非法 JSON 时会被写成不可用配置；
- 列表直接返回 JSON 字符串，前端无法按对象使用；
- 编辑未变化时依赖 `rowCount()` 判断存在，可能误报“网关不存在”。

## 3. 代码修改

文件：`src/Http/Controllers/AdminFeatureController.php`

### 网关列表

`channelGatewayList()` 将 `options` 从数据库 JSON 字符串解码为数组后返回，前端收到的数据结构固定为对象。

### 单条创建和编辑

新增 `channelGatewayValues()`，创建、编辑、批量导入共用同一套校验：

1. 名称和地址不能为空；
2. `addr` 必须包含合法的 HTTP 或 HTTPS scheme 和 host；
3. 支付方式必须存在且启用；
4. 通道必须存在且启用；
5. `pay_channel.type` 必须等于 `pay_type`；
6. 通道插件必须存在、启用、运行，并支持当前支付方式；
7. `options` 必须是数组或合法 JSON 对象；
8. `active_time` 必须是非负整数。

编辑时先查询记录是否存在，再执行更新，不再用“更新影响行数”判断记录存在。

### 批量导入

批量导入不再静默跳过错误记录。遇到非数组、空字段、错配支付方式、非法地址或非法配置时，直接返回中文 422，避免部分错误数据进入数据库。
