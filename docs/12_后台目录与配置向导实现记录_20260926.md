# 2026-09-26 后台目录与配置向导实现记录

## 本轮目标

把后台以下接口从明确 `501` 改成基于本 PHP 项目真实目录、数据库和插件目录的可用逻辑：

- `GET /api/admin/option/templates`
- `GET /api/admin/connect/items`
- `GET /api/admin/connect/templates`
- `GET /api/admin/tools/config-wizard/check`
- `GET /api/admin/sms/plugin/list`
- `GET /api/admin/sms/plugin/form-items`

本轮只修改 `C:\Users\Administrator\Desktop\重构PHP`，不修改旧 Go 工程、服务器原 Go 目录、生产站点或其他目录。

## 原问题

这些后台菜单会请求目录类接口，但 PHP 版本此前统一返回 `501`：

- 基础设置页不能加载前台/后台模板目录。
- 通知模板页不能加载通知通道、事件变量和矩阵数据。
- 配置向导不能检查本地目录权限、模板入口和 Redis 配置状态。
- 短信插件设置页不能读取插件 manifest；也不能区分“未安装插件”和“发送能力已上线”。
- 菜单浏览器测试把这些接口列为预期未上线，无法继续核对真实页面行为。

## 修改文件

### `src/Http/Controllers/AdminFeatureController.php`

#### `optionTemplates()`

实现步骤：

1. 校验管理员登录态。
2. 扫描 `public/index`、`public/pay`、`public/cashier`、`public/user`。
3. 每个模板类型都返回本地默认模板项。
4. 如果存在子目录 `manifest.json`，读取为额外模板项。
5. 后台模板返回 `public/admin` 当前默认模板。
6. 返回前端实际读取的 `frontend` 和 `backend` 字段。

作用：基础设置页可以加载本地模板目录；没有外部模板时只显示真实默认模板，不伪造应用商店模板。

#### `connectItems()`

实现步骤：

1. 返回后台通知模板页需要的通道列表：全局模板、站内通知、邮件、短信、微信公众号、WxPusher。
2. 返回事件列表：订单支付成功/失败、充值成功、提现提交/审核、工单回复、商户注册。
3. 每个事件返回可插入变量 `rules`，供前端 `msg_template_actions` 点击插入 `{{变量}}`。

作用：通知模板页可以初始化列和变量按钮。这里仅实现模板配置目录，不代表邮件、短信或第三方通知真实发送已上线。

#### `connectTemplates()`

实现步骤：

1. 查询 `notification_template` 表。
2. 按 `事件:通道` 的 `code` 和 `channel` 组装矩阵。
3. 每个事件返回一行，每个通道返回一个单元格。
4. 单元格包含前端编辑表单需要的 `id`、`code`、`name`、`channel`、`source_type`、`event_id`、`template_title`、`template_content`、`status`、`has_chose`、`is_global`。
5. 数据库没有对应模板时 `id=0`、`status=2`，前端显示为“请先配置模板内容”。

作用：通知模板页可以一比一显示矩阵并创建/编辑模板。不存在的模板不会假装已启用。

#### `writeNotificationTemplate()`

同步修正通知模板保存字段：

1. 模板名称兼容前端矩阵提交的 `template_title`。
2. 模板内容优先读取 `template_content`。
3. 通道优先读取 `source_type`。

作用：通知矩阵表单保存后，`connectTemplates()` 能读取到真实内容；不会出现页面保存成功但内容丢失。

#### `configWizardCheck()`

实现步骤：

1. 检查 `var`、`public/uploads`、`database`、`public` 是否存在和可写。
2. 检查 `public/index`、`public/pay`、`public/cashier`、`public/user`、`public/admin` 模板入口是否存在。
3. 读取 `XARR_REDIS_DSN`，返回 Redis 是否配置。
4. PHP 版本未内置 Redis 客户端连接检测时明确返回中文说明。

作用：配置向导展示真实本地状态。没有 Redis 配置时显示“使用数据库和文件运行态”，不是假连接成功。

#### `smsPluginList()` / `smsPluginFormItems()`

实现步骤：

1. 只扫描 `XARR_PLUGIN_DIR/sms/*/manifest.json`。
2. 已安装短信插件返回真实 manifest。
3. 未安装短信插件返回空 `list`。
4. 表单项只读取 manifest 中的 `form_items`、`formItems` 或 `config`。
5. `plugin_name` 为空时返回空配置项，未知插件返回中文 404。

作用：短信插件页能加载目录，但不伪造任何短信服务商，也不宣称短信发送已可用。真实发送测试接口仍保持明确未配置状态。

#### 新增私有方法

- `templateCatalogItem()`：生成默认模板目录项。
- `templateManifests()`：扫描模板 manifest。
- `notificationConnectors()`：集中定义通知通道。
- `notificationEvents()`：集中定义通知事件和变量。
- `pluginManifestsByType()`：按插件类型扫描 manifest；本轮用于 `sms`。

### `public/admin/static/js/unimplemented-feature-notice.js`

作用：已实现接口不再被前端错误边界当作“功能暂未上线”处理。

### `scripts/browser-admin-menu-test.py`

从 `expected_unimplemented` 删除以下后台接口：

- `/api/admin/option/templates`

- `/api/admin/connect/templates`
- `/api/admin/tools/config-wizard/check`

作用：浏览器菜单测试后续会把这些接口的失败视为真实失败，而不是预期 501。

### `tests/AdminFeatureCatalogTest.php`

新增独立 HTTP 回归测试：

1. 创建临时 SQLite。
2. 写入测试管理员 token。
3. 启动 PHP 内置服务。
4. 验证模板目录接口返回 `frontend/backend`。
5. 验证通知连接项返回 `connect/events`。
6. 验证通知模板矩阵包含 `global/system` 单元格。
7. 通过矩阵字段创建通知模板，再验证矩阵能读回内容。
8. 验证配置向导返回 `permission_checks/theme_checks/redis_check`。
9. 验证短信插件列表和空插件表单返回 200。

## 数据和边界规则

- 不复制服务器私有插件正文。
- 不扫描 Go 项目目录。
- 不把没有安装的短信插件伪造成服务商。
- 不把短信、邮件、微信、WxPusher 真实发送标记为上线；发送测试接口仍按未配置返回明确错误。
- 不为在线应用商店、在线版本检查、共享通道增加兜底成功。
- 通知模板使用现有 `notification_template` 表，不新增隐藏 JSON 字段。
