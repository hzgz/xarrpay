# 28_应用商店日志与系统设置修复记录_20260927

## 1. 本轮问题

本轮处理后台三个问题：

1. 应用商店扫描本地插件失败，实际 `plugins/pay/` 下已经存在插件。
2. 日志查看页面没有记录。
3. 系统设置填写后点击保存没有反应。

处理目录固定为：

```text
C:\Users\Administrator\Desktop\重构PHP
```

本轮没有修改原 Go 项目和其它桌面目录。

## 2. 原因确认

### 2.1 应用商店扫描失败

后台前端已经请求以下接口：

```text
GET  /api/admin/app-items/scan-local-plugins
POST /api/admin/app-items/load-local-plugin
POST /api/admin/app-items/scan-templates
POST /api/admin/app-items/load-local-template
```

PHP 后端之前只有应用列表和启停接口，没有本地插件扫描、加载接口，因此页面提示扫描失败与插件目录是否存在无关。

当前插件是独立目录结构：

```text
plugins/pay/jk_wechat_app/
plugins/pay/static_code/
plugins/pay/yun_qnm_lz/
plugins/pay/yun_wechat_gj_xd/
plugins/pay/yun_wechat_yyb_xd/
```

每个插件通过自己的 `manifest.json` 描述名称、类型、版本、能力和入口文件。

### 2.2 日志查看为空

旧实现只扫描项目根目录的 `var/*.log`，线上实际日志主要位于：

```text
/www/wwwlogs/
/www/server/php/81/var/log/
/www/server/nginx/logs/
/www/wwwroot/xarr/runtime/logs/
```

同时，后台测试产生的浏览器 profile 目录也在项目 `var/` 下。之前递归扫描整个 `var/` 会把这些测试目录中的 `.log` 文件错误显示为应用日志。

### 2.3 系统设置保存没有反应

基础配置接口此前在空配置数据库下返回空数组。前端基础设置页面有必填校验字段：

```text
web_index_title
web_title
admin_path
third_account_report_secret
system_plugin_maxtotal
```

因为页面模型没有这些字段，前端校验在提交前就被拦截，用户看到的结果是点击保存没有反应。后端保存接口本身可以正常写入。

## 3. 代码修改

### 3.1 `src/Application.php`

新增 `RuntimeLogger` 请求记录器。

每次进入 `/api/admin/*` 请求时，记录：

```text
时间
请求方法
请求路径
客户端 IP
User-Agent
```

应用日志文件为：

```text
var/php-YYYYMMDD.log
```

同时注册应用商店四个本地扫描和加载接口。

### 3.2 `src/Support/RuntimeLogger.php`

新增后台 API 运行日志记录实现。

日志使用 JSON Lines 格式，每个请求一行，并使用文件锁追加写入，避免并发请求相互覆盖。

### 3.3 `src/Http/Controllers/AdminFeatureController.php`

新增：

```text
appItemsScanLocalPlugins()
appItemsLoadLocalPlugin()
appItemsScanTemplates()
appItemsLoadLocalTemplate()
```

插件扫描直接读取 `plugins/<type>/<plugin>/manifest.json`，返回前端需要的插件分组、名称、路径、标题、版本、有效状态和错误信息。

日志内部记录来源、实际路径、文件大小和更新时间；返回给后台页面时只暴露逻辑路径、来源、文件大小和更新时间，不暴露服务器绝对路径。

日志扫描规则改为明确文件模式：

- 项目 `var`：只读根目录 `*.log`，不递归浏览器测试目录。
- 项目 `runtime/logs`：只读根目录 `*.log`。
- 旧版 `xarr/runtime/logs`：只读根目录 `*.log`。
- `/www/wwwlogs`：只读 `ys.973700.xyz*`、`pay.973700.xyz*`、`mpay.973700.xyz*`、`xarr*` 日志。
- PHP-FPM：只读 `php-fpm*.log`。
- Nginx：只读根目录 `*.log`。
- `XARR_LOG_DIRS`：只读配置目录根目录 `*.log`。

路径解析仍然使用扫描结果白名单，日志详情、下载、清空和流式查看不能通过请求参数访问白名单之外的文件。

### 3.4 `src/Http/Controllers/AdminController.php`

基础配置读取增加完整默认字段模型，并读取旧式独立配置项：

```text
web_title
admin_path
system_plugin_maxtotal
third_account_report_secret
...
```

因此空数据库首次打开设置页面也会得到完整表单模型；提交后统一写入 `option.base`，刷新页面可以回读保存结果。
