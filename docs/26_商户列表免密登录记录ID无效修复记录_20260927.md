# 26_商户列表免密登录记录ID无效修复记录_20260927

## 背景

用户反馈后台商户列表点击“免密登录”时报错：

- `记录 ID 无效`

该报错来自后端 ID 校验，表示 `/api/admin/user/login-ticket` 收到的商户 ID 为空或小于等于 `0`。

## 原因

本次排查确认有两处不一致：

- `public/admin/static/js/admin-a11y-fix.js` 里曾经对“免密登录”按钮做捕获阶段拦截，并从表格 DOM 的 `td` 文本里找第一个纯数字作为 ID。
- 商户列表里真实商户 ID 单元格还包含“复制密钥”等文本，DOM 抓取不可靠，可能抓到邀请人 ID、状态值等非商户 ID，例如 `0`，导致后端返回 `记录 ID 无效`。
- `src/Http/Controllers/AdminController.php::userLoginTicket()` 只读取 `id`，而商户相关接口其他位置已经统一按 `uid/user_id/id` 接收当前业务里的商户标识。

## 修改内容

### 1. 取消前端免密登录 DOM 抢先拦截

文件：

- `public/admin/static/js/admin-a11y-fix.js`

处理：

- 删除捕获阶段监听“免密登录”点击并手动 `fetch("/api/admin/user/login-ticket")` 的逻辑。
- 免密登录按钮回到后台商户列表 Vue 页面原本的处理流程：
  - 使用当前行对象 `row.id`。
  - 调用 `user.loginTicket({ id: row.id })`。
  - 成功后打开后端返回的 `login_url`。

作用：

- 不再从表格 DOM 文本猜商户 ID。
- 避免误把邀请人 ID、状态值、空值当作商户 ID。
- 避免辅助脚本抢先 `stopImmediatePropagation()` 影响页面原业务逻辑。

### 2. 后端免密票据接口统一商户 ID 字段

文件：

- `src/Http/Controllers/AdminController.php`

处理前：

```php
$id = $this->requiredId($request->all());
```

处理后：

```php
$params = $request->all();
$id = $this->requiredId(['id' => $params['uid'] ?? $params['user_id'] ?? $params['id'] ?? 0]);
```

作用：

- 后台免密登录与余额、佣金、状态等商户接口保持同一套商户 ID 读取规则。
- 当前前端传 `id` 正常。
- 当前业务内其他调用传 `uid` 或 `user_id` 时也能进入同一个校验入口。
- 仍然保留 `requiredId()` 的严格校验，空值、`0`、非法 ID 继续返回 `记录 ID 无效`。

### 3. 增加测试覆盖

文件：

- `tests/AdminFeatureCatalogTest.php`

新增：

- 原有 `id=1` 免密票据生成、兑换、重复兑换测试保留。
- 新增 `uid=1` 生成免密票据测试，确保接口字段统一后可用。

## 下次更新核对

- 商户列表“免密登录”不能再从 DOM 文本猜 ID，必须使用行数据 `row.id`。
- `/api/admin/user/login-ticket` 收到 `id=商户ID` 必须返回 `ticket/login_url`。
- `/api/admin/user/login-ticket` 收到当前业务里的 `uid=商户ID` 也必须返回 `ticket/login_url`。
- 收到空 ID 或 `0` 时继续返回 `记录 ID 无效`，这是正常严格校验，不做旧数据兜底。
