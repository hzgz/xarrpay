## 3. 本轮确认的真实错误

### 3.1 二维码解析接口缺失

后台和商户中心前端在插件表单、支付码池等输入项出现 `append_deqrocde` 配置时，会向以下地址上传图片：

```text
POST /api/qrcode/decode
multipart/form-data
字段名：file
```

前端期望成功响应：

```json
{
  "code": 200,
  "message": "解析成功",
  "data": "二维码内容",
  "redirect": ""
}
```

原 PHP 路由只有：

```text
GET /api/qrcode
```

这个路由负责生成二维码，不负责读取二维码。`POST /api/qrcode/decode` 没有注册，因此线上和本地旧版本点击“解析二维码”都会直接返回 HTTP 404。

### 3.2 不是本轮新错误的项目

以下能力在当前项目中已经明确按“未配置/未上线”契约返回中文 HTTP 501，不属于 500 或页面崩溃：

```text

/api/admin/staff/connect-channels
/api/admin/staff/passkey/list
/api/admin/system/check-version

```

## 4. 代码修改

### 4.1 `src/bootstrap.php`

新增本地二维码解码库的固定加载入口：

```text
vendor/qrcode-detector-decoder/lib/
```

同时加载该库要求的公共函数文件，并为 `Zxing\` 命名空间注册项目内 PSR-4 自动加载。

作用：

- 让解码器随纯净包部署，不依赖线上网络。
- 不依赖 Composer 运行时。
- 缺少解码库时直接启动失败，避免静默降级成假成功。

### 4.2 `vendor/qrcode-detector-decoder/`

加入纯 PHP 二维码检测和解码库，来源：

```text
https://github.com/khanamiryan/php-qrcode-detector-decoder
```

本轮下载的源码提交：

```text
17c570bb39f641cc1c4c41a46177ac491393a01d
```

保留原项目的：

```text
LICENSE-MIT
LICENSE-ASL-2.0
README.md
```

该库使用当前 PHP 8.1 的 GD 扩展读取 PNG、JPEG、GIF、WebP 和 BMP 图片。

### 4.3 `src/Support/QrCodeDecoder.php`

新增真实二维码解码服务，处理流程固定为：

1. 检查 GD 扩展。
2. 检查上传文件存在、可读且不超过 10 MB。
3. 读取图片二进制并用 `getimagesizefromstring()` 校验真实图片格式。
4. 只允许 PNG、JPEG、GIF、WebP、BMP。
5. 调用 ZXing 纯 PHP 解码器读取二维码文本。
6. 无法识别时返回明确中文错误，不返回空字符串或伪造结果。

### 4.4 `src/Http/Controllers/MerchantController.php`

新增 `decodeQrcode()`：

- 同时接受前端组件使用的 `file` 和 `image` 字段。
- 映射 PHP 上传错误为中文提示。
- 拒绝非 HTTP 上传临时文件。
- 成功返回 `data=二维码文本` 和 `message=解析成功`。

### 4.5 `src/Application.php`

注册：

```text
POST /api/qrcode/decode
```

## 5. 新增回归测试

新增：

```text
tests/QrCodeDecodeTest.php
```

覆盖四类行为：

1. 缺少文件：HTTP 422，中文提示要求上传二维码图片。
2. 非图片文件：HTTP 422，拒绝伪造 MIME。
3. 有效图片但没有二维码：HTTP 422，提示未识别到二维码。
4. 有效二维码图片：HTTP 200，精确回填原二维码文本。

测试使用项目自身 `QrCode` 生成隔离 PNG，再通过真实 multipart HTTP 请求发送到接口，不调用线上服务、不写线上数据库。
