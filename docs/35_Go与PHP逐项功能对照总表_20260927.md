#### 2. 安全二次验证默认关闭

涉及文件：

```text
src/Http/Controllers/AdminController.php
src/Http/Controllers/MerchantController.php
src/Http/Controllers/MerchantFeatureController.php
tests/AdminSecurityTest.php
tests/MerchantSecurityTest.php
tests/MfaSecurityFlowTest.php
```

真实根因：

- 管理员和商户 `stepUpBegin()` 原先无条件创建安全票据，即使管理员没有 `mfa_secret`、商户没有启用 MFA 且没有 Passkey，也会要求当前密码。
- 敏感业务接口的 `consumeStepUpTicket()` 也无条件要求票据，导致前端即使识别到默认关闭，后端仍返回 401。

具体修改：

- 管理员没有 `staff.mfa_secret` 时，`/api/admin/security/step-up/begin` 返回 `need_step_up=false`，不创建票据。
- 商户既没有启用有效 TOTP，也没有有效 Passkey 时，`/api/security/step-up/begin` 返回 `need_step_up=false`，不创建票据。
- 管理员和商户业务侧消费票据前重新读取真实数据库安全因子；默认关闭时直接继续业务，显式启用 TOTP 或绑定 Passkey 后仍严格校验票据、用途、过期时间、用户归属和一次性消费。
- 首次绑定 MFA 在默认关闭状态下不再要求额外当前密码；MFA 开启后登录和解绑仍要求动态口令。

作用：

- “默认关闭”只关闭未配置因子时的二次验证，不删除显式启用后的安全校验。
- 前后端行为一致，避免出现前端跳过但后端仍阻塞的状态。
